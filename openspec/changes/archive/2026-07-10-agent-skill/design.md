# agent-skill — design

## Context

The dotfiles command doc carried two things: orchestration (replaced by the binary) and the triage discipline (still Claude-Code-only, still pointing at the dead script).
This change gives the discipline a home that ships with the tool.
Landscape fact recorded here because the decision is made here: **Google has deprecated the Gemini CLI in favor of the Antigravity toolchain** (2026-07), so the planned `gemini` adapter is removed and Antigravity is Google's representation in the roster; `agy plugin import claude` (verified on agy 1.1.0) makes the Claude-format skill the Antigravity install path too.

## Goals / Non-Goals

**Goals:** one canonical skill, embedded, installed natively per harness, idempotent; roster corrected.
**Non-Goals:** see proposal.

## Decisions

### D1 — Canonical file lives in `skills/`, embedded via a tiny package

`go:embed` cannot reach above its package directory, so `skills/embed.go` (package `skills`) embeds `second-opinion/SKILL.md` and exports it; `cmd/second-opinion` imports it.
The repo file is the source of truth by construction — the embed reads it directly, and a test pins the invariant.

### D2 — One document, two renderings, one import

- Claude: verbatim — YAML frontmatter (name, description) is Claude's native skill format.
- Codex: frontmatter stripped — codex custom prompts are plain markdown, filename is the command name.
- Antigravity: a minimal Claude-format *plugin*, not a third rendering of the skill. Learned empirically during implementation: `agy plugin import claude` reports "No claude extensions found" against bare `~/.claude/skills` — agy consumes plugins (`plugin.json` + `skills/`), and `agy plugin install <local dir>` accepts one (verified: validate and install both process the skill). The installer writes `~/.second-opinion/antigravity-plugin/{plugin.json, skills/second-opinion/SKILL.md}` and runs the install when `agy` is on PATH; failure is a warning, and without `agy` the directory is still written so the printed next-step command works as-is.
Alternative considered: a gemini TOML target (`~/.gemini/commands`). Rejected — the CLI it served is deprecated.

### D3 — Installer edges injected

`runSkill` takes the home directory, a `lookPath`, and an import-runner as parameters; `main` passes the real ones.
Tests run against a temp home and a recording fake — the same injectable-edges pattern `run` already uses for providers.

### D4 — Generated stamp as a comment

Each written file carries `<!-- generated by second-opinion skill install; edits will be overwritten -->` immediately after the frontmatter (or at the top for codex).
The stamp is the ownership claim that makes idempotent overwrite honest.

### D5 — Skill content: the dotfiles doc, re-grounded

The five triage steps and the "expect roughly two-thirds to fall away" calibration survive nearly verbatim — they are the accumulated judgment this change exists to distribute.
What changes: orchestration now points at the binary's real surface (exit codes, provenance line, `--provider`/env selection), the Codex-specific auth caveat generalizes to "model forcing is provider-specific; provenance reports what actually ran", and reviewer selection gains the neutrality rule: pick a reviewer that differs from the model that wrote the material — same family is fine, same model defeats the premise.

## Cold-reviewer guarantee

Untouched — this change writes files for the *calling* agent's harness and never runs a reviewer.
The skill's text actively supports the guarantee's premise by teaching callers to check the provenance line.

## Risks / Trade-offs

- [`agy plugin import claude` semantics may not cover plain skills] → **Fired, exactly as anticipated**: import skips bare skills. Resolved via the plugin-dir + `agy plugin install` path above; this note kept as the record.
- [Codex prompt format may evolve] → The rendering is one function; the file is stamped and regenerable.
- [Skill drift from CLI behavior] → The skill ships in the same repo and binary as the CLI it describes; changing flags without updating the skill is visible in one diff.
