# Stateless MCP implementation — 2026-11-14

The gateway exposes `review` and registry-only `list_providers` through stdio and authenticated loopback HTTP. Every review is assembled from explicit tool arguments and the chosen prompt. No file/URL resolution, client-context acquisition, job store, result cache, deduplication, or findings parser was added. The official Go MCP SDK is pinned at v1.8.0.

## Deterministic verification

- SDK clients exercise MCP 2026-07-28 and 2025-11-25 over stdio framing and actual loopback HTTP; a subprocess test checks command entry, clean protocol stdout, discovery, and normal exit for both versions.
- Strict schemas and validation cover unknown fields, null/wrong types, nonblank text, Unicode/surrogate errors, duplicate keys, exact text preservation, byte budgets, and timeout limits. Real JSON Schema validation checks advertised output variants.
- Executor/tool tests cover fresh provider construction, A-then-B default isolation, equal request IDs across distinct connections, fresh-server equivalence, no discovery invocation, exact request bytes, receipts, provenance, empty success, safe error mapping, malformed results, and panic recovery.
- Transport tests cover authentication/Origin/Host rejection before body reads, no session IDs, no GET/DELETE stream, explicit subscription rejection, oversized frames/bodies/responses, blocked-writer admission, and cancellation that bypasses saturated stdio admission.
- Two executing reviews reject a third without queuing; cancellation leaves the sibling alive and capacity becomes reusable. Actual stream disconnection reaches the provider in both versions/transports. A real socket slow-body test observes the ten-second read deadline.
- Shutdown tests cover cooperative cancellation and the five-second bound with a deliberately noncooperative engine-seam provider. A 2,000-request saturated HTTP stress test verifies no body reads, queued goroutines, or growing retained heap.
- Actual subprocess tests cover stdout/stderr capture overflow, discarded destinations, concurrent shared writers, gateway-token removal, active cancellation, and inherited pipes. Output overflow cannot become partial success and limits also apply to Codex fallback.
- Worst-case JSON escaping at the raw findings limit remains within the response budget; oversized provenance returns an output-limit error.

Validation: `go vet ./...`, ordinary tests, full `go test -race ./...`, and Linux/Windows cross-builds. Tests opening loopback sockets need permission outside the desktop filesystem/network sandbox. No provider binary was mocked to establish provider behavior; engine-seam test providers exercise gateway logic only.

## Limits and remaining evidence gaps

The gateway does not strengthen provider isolation. Full harness-global isolation remains unproved, especially for Antigravity; detached children outside the invocation group and Windows descendant cleanup remain uncovered. The shared conformance cancellation test has no provider readiness signal and still establishes pre-cancellation only; separate real-child tests cover active process cleanup on the host Unix platform.

Header/write/idle HTTP timeouts are configured at 10/310/30 seconds; the body deadline is exercised on a real socket, while full-duration idle and 310-second stalled-write endurance are not exercised. Cross-builds do not establish Windows runtime behavior. The heap stress check demonstrates bounded application admission for rejected work, not an operating-system connection/file-descriptor budget or exhaustive hostile-traffic proof. Review quality and model obedience cannot be established by deterministic tests. Unknown-model provenance markers remain unknown.

A lost response means unknown completion. No gateway retry or recovery endpoint exists; another call may repeat paid work. Provider-side persistence and Go memory erasure are outside the stateless application guarantee.
